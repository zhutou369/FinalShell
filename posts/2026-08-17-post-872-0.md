## 理解高分屏与 DPI 缩放的挑战

在深入解决方案之前，我们有必要简单了解一下高分屏和 DPI 缩放的工作原理。高分屏意味着在相同物理尺寸下，屏幕的像素点更多，显示内容更精细。为了保证视觉大小不变，操作系统通常会引入 DPI 缩放机制，将界面元素和字体放大，以适应高 DPI 显示。例如，在 4K 屏幕上，你可能将系统缩放设置为 150% 或 200%。

然而，并非所有应用程序都能很好地响应这种系统级的 DPI 缩放。对于一些老旧的应用程序，或者某些基于特定 UI 框架（如 Java Swing/AWT）开发的程序，它们可能无法正确识别或应用系统的 DPI 缩放设置。这就会导致在高分屏下，程序以原始像素大小渲染，使得字体和界面元素看起来非常小，如同“蚂蚁般大小”，甚至因为系统强制拉伸而变得模糊。FinalShell 正是这类受影响的 Java 应用程序之一。

## 针对 FinalShell 的最佳解决方案

针对 FinalShell 的高分屏显示问题，我们主要有以下几种解决方案，其中一些更为推荐。

### 方案一：通过 Java 运行时参数强制缩放 (推荐)

这是解决 FinalShell 在高分屏下显示问题的最有效和最推荐的方法。FinalShell 是基于 Java 运行环境构建的，我们可以通过修改 Java 虚拟机 (JVM) 的启动参数，强制指定其 UI 缩放比例，从而达到清晰放大的效果。

1.  **定位 FinalShell 的启动配置文件夹**
    *   **Windows 用户：** 通常在 FinalShell 的安装目录下，例如 `C:\Program Files\FinalShell`。在该目录下，你需要找到一个名为 `finalshell.vmoptions` 的文件。如果找不到，可能是在 `~/.finalshell` 目录下，或者应用程序数据目录中 (`%APPDATA%\FinalShell`)。
    *   **Linux/macOS 用户：** 通常在用户主目录下的 `.finalshell` 隐藏文件夹中，例如 `~/.finalshell/`。你需要找到 `finalshell.vmoptions` 或类似的配置文件。

2.  **编辑 `finalshell.vmoptions` 文件**
    使用文本编辑器（如记事本、VS Code、Sublime Text 等）打开 `finalshell.vmoptions` 文件。
    在该文件的末尾添加以下一行或两行参数：

    ```
    -Dsun.java2d.uiScale=X.0
    ```
    或者
    ```
    -Dsun.java2d.dpiaware=false
    -Dsun.java2d.uiScale=X.0
    ```
    请注意：
    *   `X.0` 是你希望的缩放比例。
        *   如果你的系统缩放是 150%，可以尝试 `1.5`。
        *   如果你的系统缩放是 200%（即 4K 屏幕上常用的），可以尝试 `2.0`。
        *   你可以根据实际效果调整 `X` 的值，比如 `1.25`, `1.75` 等。
    *   `-Dsun.java2d.dpiaware=false` 这个参数的作用是告诉 Java 虚拟机不要尝试根据系统 DPI 进行自动缩放，而是完全依赖 `uiScale` 参数。这在某些情况下可以避免模糊，强制实现我们设定的缩放。如果只设置 `uiScale` 效果不佳或仍然模糊，可以尝试同时添加 `dpiaware=false`。

    例如，对于 4K 屏幕，我通常推荐设置为 `2.0`：
    ```
    -Dsun.java2d.dpiaware=false
    -Dsun.java2d.uiScale=2.0
    ```

    ![FinalShell UI scaling configuration screenshot](/static/images/photo-1552664730-d307ca884978.jpg)
    *编辑 `finalshell.vmoptions` 文件并添加 Java 缩放参数，这是解决 FinalShell 高分屏显示问题的关键一步。*

3.  **保存文件并重启 FinalShell**
    保存对 `finalshell.vmoptions` 文件的修改，然后完全关闭 FinalShell 并重新启动。你会发现 FinalShell 的界面已经按照你设定的比例进行了放大，字体和界面元素都变得清晰可读了。

### 方案二：调整系统级程序兼容性设置 (Windows 特有)

对于 Windows 用户，可以通过修改应用程序的兼容性设置来尝试解决。这种方法通常不如直接修改 Java 参数精确和清晰，但在某些情况下也可以作为备选。

1.  **找到 FinalShell 的可执行文件**
    在 FinalShell 的安装目录下找到 `FinalShell.exe`。如果你不确定安装位置，可以在桌面快捷方式上右键点击“打开文件所在位置”。如果你是第一次在 Windows 系统上安装 FinalShell，可以参考 [FinalShell Windows 安装教程](/posts/cn-finalshell-windows-install-setup/)。

2.  **修改兼容性设置**
    *   右键点击 `FinalShell.exe`，选择“属性”。
    *   切换到“兼容性”选项卡。
    *   点击“更改高 DPI 设置”。
    *   在弹出的窗口中，勾选“替代高 DPI 缩放行为”，然后在下面的下拉菜单中选择“系统(增强)”或“应用程序”。
        *   **系统(增强)**：由系统通过 GDI 缩放，通常比“系统”更清晰，可能会有更好的效果。
        *   **应用程序**：表示应用程序自身处理 DPI 缩放，但这通常是问题的原因所在。如果尝试“系统(增强)”无效，可以尝试“应用程序”，但效果可能不佳甚至模糊。
    *   点击“确定”保存设置，然后重启 FinalShell。

### 方案三：FinalShell 内部字体设置微调

上述两种方法主要解决的是 FinalShell 整个应用程序界面的缩放问题。如果仅仅是终端连接部分（例如你连接到服务器后敲命令的区域）的字体太小，你可以在 FinalShell 内部进行调整。

1.  **打开 FinalShell 选项**
    在 FinalShell 菜单栏中选择“工具” -> “选项” (Options)。

2.  **调整终端字体**
    *   在选项窗口中，找到“终端” (Terminal) 或“字体” (Font) 相关的设置。
    *   你可以选择一个更大的字体大小，例如 14pt、16pt 甚至更高。同时，你也可以更换字体，选择一个更适合阅读的等宽字体（如 Sarasa Term SC、Cascadia Code、Fira Code 等）。
    *   如果连接服务器后字体仍然太小，这个调整将直接影响你的操作体验。比如在进行 [FinalShell 首次连接服务器](/posts/cn-finalshell-first-server-connection/) 后，命令行的字体大小就受此影响。

    *在 FinalShell 的选项设置中调整终端字体大小，可以单独优化命令行的显示效果。*

3.  **保存并查看效果**
    保存设置后，打开或切换到任意一个终端连接窗口，查看字体大小是否符合你的要求。

### 方案四：调整操作系统全局显示缩放 (不推荐)

这是一种治标不治本的方法，而且会影响到所有应用程序的显示。通常不推荐为了一两个应用而全局修改系统设置。

1.  **Windows 用户：** 右键桌面 -> 显示设置 -> 缩放与布局 -> 更改文本、应用和其他项目的大小。
2.  **Linux 用户：** 进入系统设置 -> 显示 -> 缩放。

如果你已经尝试了上述方法，并且确认你的高分屏问题主要集中在 FinalShell 上，那么调整系统全局缩放就没有必要了。

## 操作步骤详解与注意事项

结合上述方案，我们来重点强调一下通过 Java 运行时参数强制缩放的详细操作步骤和注意事项。

**详细操作步骤 (以 Windows 为例，Linux/macOS 类似)：**

1.  **关闭所有 FinalShell 进程：** 确保 FinalShell 应用程序完全关闭，包括系统托盘区的图标。
2.  **导航到配置文件夹：**
    *   打开文件资源管理器。
    *   在地址栏输入 `%APPDATA%\FinalShell` 并回车，这通常会带你到用户应用程序数据目录下的 FinalShell 配置文件夹。
    *   如果此目录没有 `finalshell.vmoptions`，请检查 FinalShell 的安装目录 (例如 `C:\Program Files\FinalShell`)。
3.  **备份 `finalshell.vmoptions` (重要)：** 在修改任何配置文件之前，养成备份的习惯。将 `finalshell.vmoptions` 文件复制一份并重命名为 `finalshell.vmoptions.bak`。
4.  **编辑 `finalshell.vmoptions`：**
    *   右键点击 `finalshell.vmoptions` 文件，选择“打开方式” -> “记事本”或其他文本编辑器。
    *   在文件的最末尾添加以下两行：
        ```
        -Dsun.java2d.dpiaware=false
        -Dsun.java2d.uiScale=2.0
        ```
        （请根据你的实际需求调整 `uiScale` 的值，如 `1.5`, `1.75` 等。如果你的系统缩放为 150%，尝试 `1.5`；如果为 200%，尝试 `2.0`。）
5.  **保存文件：** 确保你保存了修改。如果提示权限问题，可以尝试将文件复制到桌面编辑后再复制回去，或者以管理员权限启动文本编辑器。
6.  **重新启动 FinalShell：** 启动 FinalShell，观察界面和字体是否已正常缩放且清晰。

**注意事项：**

*   **重启是关键：** 任何对 `vmoptions` 文件的修改都需要完全重启 FinalShell 才能生效。
*   **尝试不同缩放值：** `uiScale` 的值并非一成不变，你需要根据你的显示器分辨率、系统缩放设置以及个人视觉习惯进行微调，直到找到最舒适的显示效果。
*   **模糊问题：** 如果缩放后界面变得模糊，尝试只保留 `-Dsun.java2d.uiScale=X.0` 而去除 `-Dsun.java2d.dpiaware=false`，或者反之。有时候，操作系统和 Java VM 的协调方式不同，会导致不同的效果。
*   **配置文件的位置：** 如果你在默认位置找不到 `finalshell.vmoptions`，可以尝试在 FinalShell 安装目录下搜索 `.vmoptions` 文件，或者检查用户的应用程序数据目录。

## 常见问题

### 1. 为什么我修改了参数还是无效？

*   **是否完全重启 FinalShell？** 确保你已彻底关闭 FinalShell，包括任务栏或系统托盘中的所有进程。
*   **文件路径是否正确？** 确认你修改的是正确的 `finalshell.vmoptions` 文件。在 Windows 上，可能存在于安装目录或 `AppData` 目录。
*   **参数拼写错误？** 仔细检查参数 `-Dsun.java2d.uiScale=X.0` 和 `-Dsun.java2d.dpiaware=false` 是否有拼写错误、多余空格或字符。
*   **Java 版本问题？** 极少数情况下，特定 Java 版本可能对这些参数支持不佳。不过对于当前主流的 Java VM 来说，这些参数都是标准支持的。

### 2. 界面现在是大了，但有点模糊怎么办？

*   **尝试不同的 `uiScale` 值：** 微调 `X.0` 的值，例如从 `2.0` 调整为 `1.75` 或 `2.25`，看看是否有改善。
*   **`dpiaware` 参数的取舍：** 尝试去除 `-Dsun.java2d.dpiaware=false`，只保留 `-Dsun.java2d.uiScale=X.0`。反之亦然。有时候，禁用 DPI 感知反而能带来更清晰的效果，有时则不然。
*   **Windows 兼容性设置：** 如果你是 Windows 用户，且以上方法仍然模糊，可以尝试方案二中提到的兼容性设置，特别是选择“系统(增强)”。

### 3. 调整字体后，行间距也变大了怎么办？

这通常发生在 FinalShell 内部调整终端字体后。部分字体在放大后行间距会显得过大。
*   **尝试更换字体：** 不同的等宽字体（如 JetBrains Mono, Fira Code, Sarasa Term SC）在高DPI下的渲染和行间距表现可能不同，多尝试几种。
*   **FinalShell 内部可能没有独立的行间距设置：** 大多数终端工具不会提供单独的行间距设置，它通常是字体本身属性或与字体大小关联。

### 4. Mac 用户有类似问题吗？

Mac 系统在处理高 DPI 显示方面通常比 Windows 或 Linux 桌面环境做得更好，原生应用程序很少遇到此类问题。但由于 FinalShell 是基于 Java 的应用，理论上也有可能出现类似情况。如果遇到，方案一（修改 `finalshell.vmoptions`）依然是最推荐的解决方案。Mac 上的 `finalshell.vmoptions` 文件通常位于 `~/.finalshell/` 目录下。
