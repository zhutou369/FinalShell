## 常见问题

### SFTP 传输速度慢怎么办？

SFTP 传输速度受多种因素影响：
1.  **网络带宽：** 检查本地网络和服务器网络的带宽限制。
2.  **服务器负载：** 服务器 CPU、内存或磁盘 I/O 过高可能影响传输速度。
3.  **距离：** 物理距离越远，网络延迟越高。
4.  **文件数量与大小：** 传输大量小文件通常比传输少量大文件慢，因为每次传输都需要建立连接和验证。
5.  **加密开销：** SFTP 基于 SSH，数据传输会进行加密解密，对 CPU 有一定消耗。
FinalShell 自身在传输协议优化方面已经做得很好，你可以尝试在网络空闲时传输，或者考虑升级服务器带宽。

### SFTP 上传失败如何排查？

1.  **权限问题：** 检查远程目标目录的写入权限。确保当前连接的用户有权限在该目录创建或修改文件。FinalShell SFTP 界面可以直接查看和修改文件权限。
2.  **磁盘空间不足：** 远程服务器的磁盘空间可能已满。在 SSH 终端中使用 `df -h` 命令检查磁盘使用情况。
3.  **文件锁：** 目标文件可能被其他进程占用。
4.  **网络中断：** 检查网络连接是否稳定。
5.  **防火墙：** 服务器或本地防火墙可能阻断了连接。

### 如何确保 SFTP 传输安全？

SFTP 本身就是基于 SSH 的安全文件传输协议，数据在传输过程中是加密的。以下措施可以进一步增强安全性：
1.  **使用 SSH 密钥对登录：** 相较于密码登录，密钥对登录更为安全。FinalShell 完全支持 [SSH 密钥对登录](/posts/cn-finalshell-ssh-keypair-login/)。
2.  **禁用 root 用户直接登录 SFTP：** 尽量使用普通用户登录，并通过 `sudo` 进行提权操作。
3.  **最小权限原则：** 为 SFTP 用户设置最小必要的文件访问权限，确保其只能访问指定目录。
4.  **定期更换密码/密钥：** 保持密码复杂性，并定期更新。
5.  **启用服务器防火墙：** 只开放必要的端口（例如 SSH 默认的 22 端口）。
